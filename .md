structure of the project  : 

What do these directories mean?
- data/raw/: Original downloaded data, preserved without modifications.
- data/processed/: Cleaned and transformed datasets.
- data/features/: Features prepared for machine learning.
- notebooks/: Initial exploration and experiments.
- src/: Reusable Python code.
- sql/: Database schemas and analytical queries.
- tests/: Automated tests for your pipeline.
- logs/: Logs generated by your ingestion and processing code.



| Stage | Technology | What you'll implement |
|---|---|---|
| Environment | Docker, Docker Compose | Containerize and orchestrate our services |
| Data ingestion | Python, REST APIs, S3 | Retrieve and ingest transit data |
| Data lake | Parquet, S3-compatible storage | Organize raw and processed datasets |
| Data processing | Pandas, PySpark | Clean, transform, and enrich data |
| Data quality | Pytest, custom validation rules | Detect missing values, duplicates, and invalid records |
| Database | PostgreSQL | Store structured transit data |
| SQL analytics | PostgreSQL, advanced SQL | Calculate delays, route metrics, and other indicators when supported by the data |
| Streaming | Apache Kafka | Produce and consume transit events |
| Stream processing | Spark Structured Streaming | Process incoming events |
| Orchestration | Apache Airflow | Schedule and monitor ETL pipelines |
| Monitoring | Grafana | Visualize pipeline health and transit metrics |
| Deployment | Docker Compose | Run the complete local platform |
